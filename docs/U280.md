# Experimental U280 integration

The U280 changes were integrated with upstream `12c4222a41c26cb9ef8ab936ffa8c9e8441bf63d`
(sigmoid refactor) and checked on October 29, 2026. The shared manifest includes
`rtl/math/sig_pkg.sv` after `ternip_pkg.sv`, so elaboration, RTL simulation and
Vivado packaging use the new package. All 34 Python tests, elaboration (zero
errors, 287 warnings), arithmetic/broadcast RTL tests, and portable-controller
tests pass. Two-lane TP256/VP8 RTL/C++ co-simulation passes its 16 protocol cases
and matches portable state, scratch and control outputs byte-for-byte on the
mixed-prompt recurrent fixture. The full 370M and perplexity results below are
from earlier runs; they were not repeated for this integration. FPGA synthesis,
hardware emulation and card performance remain unverified.

The corrected MMfreeLM-370M portable numerical path passes the held-out quality
gate: perplexity 20.955623 versus 20.834535 for the pinned upstream BF16 model,
a relative degradation of **0.5812%** (limit 1%). Both evaluations use all 163
complete 2048-token WikiText-2 raw test windows, scoring 333,661 tokens.

Actual `ternip_core` matrix tiles now execute inside a two-lane RTL/C++
co-simulation of the complete model. The corrected checkpoint's one-token test
matches the portable controller byte-for-byte for state, scratch and control.
The controller and FP32 vector operations run as C++ in this simulation;
synthesized AMD floating-point operators are not yet numerically qualified.
No xclbin has been built, no U280 has been tested, and there is no measured
FPGA tokens/s figure or qualified throughput winner.
Machine-readable results are in [U280-validation.json](U280-validation.json),
with detailed evidence under `build/u280/reports/` on the development machine.

## What is implemented

- The local `db37abbe7a1319c1dcbb92f2ff2f94a31a1f6086` core is retained.
  The original manifest/signature are archived under `accelerator/regression/db37abb`;
  the edited development manifest is unsigned.
  Its FuseSoC manifest now lists the latency equalizer, removes the nonexistent
  configuration package and obsolete remote provider, declares a pinned BaseJump
  dependency, and injects `TERNIP_CFG` explicitly. `RegressionCfg` is a
  single-vector 16-bit regression configuration, not a selected LM format.
- `ternip_core_lanes` replicates that core with independent ports/registers and
  enforces `Cfg.BatchSize=1`. `ternip_weight_broadcast` tracks each lane's receipt
  of a beat under independent backpressure. The tile-group AXI streams connect real cores to the full-model HLS controller;
  see [the protocol](U280-tile-protocol.md).
- Immutable checkpoint/tokenizer/reference locks, verified acquisition, packed
  two-bit weights, tensor scales/shapes, non-ternary parameters, relocations,
  model IR, device ABI, memory layout, and a numerical-format manifest.
- Independent graph-level Python reference and tiled IR emulator, including
  embedding, recurrent lower bounds/state, residuals, channel mixing, normalized
  quantized output projection and lowest-ID greedy tie breaking.
- A portable C++/Vitis HLS **reference backend** executes the full model/token
  loop, reuses weights across active lanes, streams vocabulary argmax, preserves
  state, and handles prompts, EOS, limits, cancellation and output backpressure.
  `TERNIP_DEBUG_LOGITS` optionally stores logits for validation.
- An experimental XRT runtime resolves kernel argument groups, checks capacity
  and image/target identity, submits independent groups concurrently, and offers
  `submit`, `advance`, `collect`, `cancel`, and `reset`. Mocked tests do not establish
  compatibility with a real XRT installation. Grouped allocation fails closed
  unless explicitly verified and exposed by the installed metadata API.
- DDR/HBM descriptors, connectivity generation, conservative allocation planning,
  candidate enumeration, quality comparison and warm-resident benchmark helpers.

Two backends are retained. `hls-reference` computes integer dots in C++; the
new `rtl-tiles` backend sends padded 256-element matrix tiles to replicated
single-vector cores, broadcasts weights with per-lane acknowledgements, and
accumulates tile results in int32 before applying scales. Whole-vector
normalization stays in the controller. Both preserve the original instruction
format. The legacy regression configuration remains available.

The numerical emulator shares scalar C++ arithmetic with the controller and
uses CUDA only for exact int8-to-int32 dot products. Its final logits/state
match the portable controller byte-for-byte on the checked fixtures. FP32
vectors are a quality-gated candidate, not a claim about synthesized operator
rounding. Preliminary fixed-point vector-boundary screens do not constitute a
complete fixed-point implementation or qualification.

## Pinned model and numerical contract

The checkpoint is `ridger/MMfreeLM-370M` at
`4c799d7e1fcc66093a27acf36ab2faffd8bb9626`; file SHA-256 hashes are in
`accelerator/locks/370m.json`. The complete downloaded checkpoint was hash
verified before export. It has 24 layers, hidden size 1024, channel-mixer width
2816, vocabulary 32000, learned lower bounds, and no short convolutions.
The original implementation is pinned to
`ridgerchu/matmulfreellm@8222c153636c04bc322f1c99d927ff4499c40a06`.

Important source-derived details:

- Upstream calls `g_norm(g_proj(x), recurrent_output)`: normalize the projected
  gate, then multiply by SiLU of recurrent output. Reversing the inputs changes
  the graph.
- `FusedBitLinear` calls a helper with default epsilon **1e-6**. Its stored
  `norm.eps=1e-8` is not forwarded. All its projections, including the vocabulary
  head, use the fused helper. The unfused implementation has different rounding
  and epsilon behavior; it is not an interchangeable reference.
- Activations use whole-logical-vector RMS/absmax and half-away-from-zero int8
  rounding. Ternary weights use a per-matrix mean-absolute scale and ties-to-even
  rounding. Padding is excluded from normalization and scaling statistics.
- Int32 dot products accumulate across all input tiles before rescaling. Matrix
  rows are padded to the selected tile and columns to a 512-bit weight beat (256
  ternary values). Codes are `00=0`, `01=+1`, `11=-1`; `10` is rejected.
- The candidate uses FP32 vectors/scales/state and integer dot products. Upstream
  BF16 materialization, reductions, and recurrent cache rounding can differ.
  The exporter defaults to `upstream-bf16`: all 145 matrices were audited against
  the pinned upstream weight quantizer with exact code/dequantized-value matches.
  The old FP32 weight quantizer changed 7,449,387 codes and failed the quality gate;
  it is retained only as an explicit regression option.

Verified allocation for the exported model (bytes, aligned to 4096):

| Allocation | Bytes |
|---|---:|
| Packed weights | 85,262,336 |
| FP32 non-ternary parameters | 132,333,568 |
| Model IR | 49,152 |
| Conservative scratch per lane | 200,704 |
| Recurrent state per lane | 98,304 |

The weights fit one 256 MiB pseudo-channel. The HBM planner dedicates weight banks
per group and places its state/control in a separate minimal contiguous range,
including replicated embeddings and parameters. This is capacity planning, not
verified XRT grouped allocation or a bandwidth measurement. The sweep currently
emits 396 candidates; none is qualified. A 512-bit port at 300 MHz has a 19.2 GB/s
payload ceiling per direction before overhead, irrespective of board aggregate HBM bandwidth.

## Reproduce software checks

Commands below run from the repository root unless noted. Generated artifacts
belong under ignored `build/`, never source control.

```sh
python -m pip install -e './accelerator[export,test]'
python -m pytest accelerator/tests -q
python accelerator/scripts/bootstrap_deps.py --output build/basejump_stl
python accelerator/scripts/lint.py --bsg build/basejump_stl
python accelerator/scripts/rtl_tests.py
make -C accelerator cpu
make -C accelerator rtl-model-test BSG=../build/basejump_stl VERILATOR=verilator
```

The small FU/broadcast tests use Verilator 5.032. Full-core tile tests used the
PyPI Verilator 5.48.0 wheel (binary revision
`vUNKNOWN-built20260516-4e853d8`, reporting 5.49) and a C++20 compiler. Elaboration uses pyslang
9.1.0. The core has pre-existing width/sign warnings; an elaboration pass is not a
clean lint or complete functional-unit regression claim. The arithmetic test
covers add/sub only; other FUs still require broader randomized coverage. Full-core tile tests cover
load/import/GO/export/store, extrema, stalls and reset. Two-lane tests cover
TP256/VP8, TP128/VP4 and TP256/VP16, mixed active masks and malformed headers.
The RTL model runner also builds the portable controller, requires byte-identical
state/scratch/control outputs, and records source and input hashes. It deletes
any stale passing report before building, so failed builds cannot look successful. The broadcast test exercises 10,000 cycles,
including resets while stalled. Scripts propagate failing subprocess exit codes.

```sh
ternip-accel fetch --lock accelerator/locks/370m.json --output build/checkpoint
ternip-accel export --lock accelerator/locks/370m.json \
  --checkpoint build/checkpoint --output build/370m-bundle
ternip-accel lower build/370m-bundle --output build/370m-device
ternip-accel generate build/370m-bundle --tokens 1,15043 --limit 8
python accelerator/scripts/prepare_checkpoint_test.py build/370m-bundle \
  --output build/370m-cpu-test
build/cpu_runner build/370m-cpu-test
python accelerator/scripts/check_device_test.py build/370m-cpu-test
```

The C++ runner is compiled with two lanes by `make cpu`; the real-model smoke test
also uses two lanes. The test checks one generated token and recurrent state;
it does not establish long-sequence or RTL equivalence. `make cpu` uses a fresh
output directory; remove or choose a new **generated** case directory to repeat
preparation. Checkpoint acquisition resumes incomplete downloads and rejects
hash mismatches.

## Build candidates on the intended machine

Initial toolchain candidate: Vivado/Vitis 2022.2, XRT 2.14.354 and
`xilinx_u280_gen3x16_xdma_1_202211_1`. These were not installed on the development
machine. The installed platform must independently confirm the part, SLRs,
memories and clocks; the recorded platform name is not a compatibility guarantee.

```sh
ternip-accel target accelerator/targets/u280-hbm-rtl.json \
  --bundle build/370m-bundle --hbm --output build/hbm-target
python accelerator/scripts/build.py \
  --target accelerator/targets/u280-ddr-rtl.json --output build/ddr-emulation --mode hw_emu --bsg build/basejump_stl
python accelerator/scripts/build.py \
  --target build/hbm-target/target.json --output build/hbm-implementation --mode hw --bsg build/basejump_stl
ternip-accel sweep accelerator/targets/u280-hbm-rtl.json \
  build/370m-bundle --output build/candidates.json
```

The build recipe packages the RTL tile group as a free-running kernel, compiles
the HLS controller, and links their AXI streams with explicit SLR placement and
DDR/HBM connectivity. Source, headers, recipe, target and platform evidence
participate in the build hash. `platforminfo` parsing fails closed on missing
part, memory, SLR or clock evidence. Its schema adapter still needs validation
against the installed AMD platform. Normal timing checks stay enabled and a
routed post-hook fails on negative setup/hold slack. Inspect unconstrained paths,
resource usage and actual memory connectivity before accepting an image.

```python
from ternip_accel.xrt_runtime import XrtRuntime
# target is the resolved JSON descriptor used to build this exact image.
runtime = XrtRuntime("build/ddr-emulation/ternip.xclbin", target,
                     "build/370m-device", "build/ddr-emulation/build.json")
runtime.submit("request-1", token_ids, limit=64)
runtime.advance(quantum=8)   # device performs layers and tokens internally
new_ids, status = runtime.collect("request-1")
```

Use explicit BDF `identifier=` when multiple U280s are present. Calls occur at
command boundaries; this prototype API is not thread-safe. `advance` starts all
active groups before waiting. Each group has its own weight master/allocation.
Cancellation is applied at the next scheduling boundary. Model data stays on
card; ordinary results contain token IDs. Benchmark latency is host-observed at
quantum boundaries. Current counters count logical events, not compute/memory/
normalization stall cycles; the full requested hardware counter set is pending.

## Quality and remaining gates

WikiText-2 raw is pinned in `accelerator/locks/wikitext2.json`. Prepare validation
and test separately; calibration must never use test data. Preparation joins raw
rows with double newlines, applies the pinned tokenizer with special tokens, and
records a token hash. Evaluation resets state for each nonoverlapping 2048-token
window, scores 2047 next-token predictions, and reports dropped remainder tokens.

```sh
python accelerator/scripts/prepare_quality.py --checkpoint build/checkpoint \
  --lock accelerator/locks/370m.json --split test --output build/wikitext-test
python accelerator/scripts/upstream_quality.py --reference-repo build/reference \
  --checkpoint build/checkpoint --lock accelerator/locks/370m.json \
  --tokens build/wikitext-test/tokens.npy --provenance build/wikitext-test/provenance.json \
  --output build/upstream-quality.json
make -C accelerator numerics
python accelerator/scripts/controller_quality.py --bundle build/370m-bundle \
  --library build/libternip_numerics.so --tokens build/wikitext-test/tokens.npy \
  --provenance build/wikitext-test/provenance.json --output build/candidate-quality.json
ternip-accel compare-quality build/upstream-quality.json build/candidate-quality.json \
  --output build/quality-gate.json
```

Install the optional quality dependencies and the pinned upstream repository in a
compatible Linux CUDA/Triton environment. The upstream evaluator requires a clean
checkout at the pinned revision and does not substitute the candidate reference.
Use `accelerator/requirements-quality.txt` with Linux Python 3.10.16. Both model
and dataset revisions are immutable. The recorded full test evaluation passed;
GPU screening reports are explicitly ineligible for qualification. The corrected
bundle hash is `87451eb5cdf5dae2cebd5d6e3494eb282240291573fb164a4a599656c7d73305`.

Corrected-weight exploratory calibration used eight validation windows. The
upstream perplexity was 15.648642; GPU FP32 screening gave 15.751384,
Q32.8 vector-boundary rounding 15.717515, and Q32.16 rounding 15.744822.
These are screens with floating-point operations between boundaries, not
complete fixed-point datapaths. Neither fixed-point candidate has a held-out
hardware-numerical quality gate. The FP32 portable path remains the qualified
numerical baseline while FPGA operator validation is pending.

Outstanding work for the full accepted plan:

1. Extend fixed-point exploration and verify synthesized FPGA vector arithmetic
   against the portable numerical contract that passed the <=1% quality gate.
2. Validate the packaged RTL/HLS connection in AMD emulation, including complete
   synthesized token/state traces. Current full-model co-simulation uses C++ vectors.
3. Validate HLS synthesis/emulation and XRT allocation against the installed U280
   shell; validate DDR before HBM, grouped BOs and concurrent traffic.
4. Expand FU, reset, cancellation/backpressure and long-sequence RTL coverage;
   validate the C++ backend across long real-model sequences and all queue cases.
5. Add cycle/stall counters, synthesize/route feasible candidates, then perform
   repeated on-card quality/correctness/throughput measurements. Only then choose
   a winner. `qualified_winner` rejects reports without all qualification gates.
